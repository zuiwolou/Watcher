### 推荐工作流（先本地）

1. **复制配置模板并留空等待填写**  
   - [`configs/external_credentials.example.yaml`](../../configs/external_credentials.example.yaml) → `configs/external_credentials.yaml`  
   - [`frontend/admin/.env.example`](../../frontend/admin/.env.example) → `.env`  
   - [`frontend/portal/.env.example`](../../frontend/portal/.env.example) → `.env`
2. **生成带本机信息的申请说明**（白名单、`applicationId`、Debug SHA1、Bundle ID）：  
   ```powershell
   powershell -File tools/scripts/gen-api-key-guide.ps1
   ```  
   输出：[`docs/generated/API密钥申请说明.md`](../generated/API密钥申请说明.md) 与 `申请速查.txt`  
   （执行 `.\pack.ps1` 打包时也会自动生成到发布包 `docs/`）
3. 打开生成文档，按表去百度/Apple/Firebase 申请，把 AK/路径填回 `external_credentials.yaml` 与各端 `.env` / dart-define。

## 1. 需要什么（总览）

| 优先级 | 用途 | 凭证类型 | 阻塞任务 | 申请主体 |
| --- | --- | --- | --- | --- |
| P0 | Web/APP 百度地图 | 百度地图 **AK**（可多端多 Key） | E4.2 | 公司百度开放平台账号 |
| P0 | iOS 告警系统通知 | **APNs** Auth Key（或证书） | E4.3 | Apple Developer 账号 |
| P0 | Android 告警系统通知 | **FCM**（Firebase）服务账号 / Server Key | E4.3 | Google Cloud / Firebase 项目 |
| P1 | 国内 Android 厂商通道 | 华为/小米/OPPO/vivo 等推送凭证 | E4.3 加深 | 各厂商开放平台 |

| P1 | iOS 真机/上架 | Apple **开发/发布证书** + Provisioning Profile | APP 交付 | Apple Developer |

## 2. 百度地图 AK（E4.2）

### 2.1 要申请几把 Key

需求要求 **Portal / Admin / APP** 统一百度地图能力。实践上建议拆成多把 AK，便于配额与安全隔离：

| 控制台应用类型 | 申请到的密钥名 | 配置字段名 |
| --- | --- | --- |
| 浏览器端 → **JavaScript API** | **AK** | `baidu_map.javascript_api_ak`（或 `_admin` / `_portal`） / `VITE_BAIDU_JAVASCRIPT_API_AK` |
| **Android SDK** | **AK** | `baidu_map.android_sdk_ak` / `BAIDU_ANDROID_SDK_AK` |
| **iOS SDK** | **AK** | `baidu_map.ios_sdk_ak` / `BAIDU_IOS_SDK_AK` |
| 服务端 → **Web 服务 API**（可选） | **AK** | `baidu_map.web_service_api_ak`（勿下发前端） |

开发/测试环境可先申请一套「不绑域名」或绑 `localhost` 的测试 AK；生产必须绑域名/包名。

#### 本地开发怎么填白名单（推荐先这样做）

1. 创建应用时类型选 **浏览器端（JavaScript API）**。
2. 域名白名单只填：
   - `localhost`
   - 若用手机/同事机访问你电脑，再加本机局域网 IP，如 `192.168.1.10`（`ipconfig` 查看）
3. **不要**填 `admin.example.com`（那是生产示例）；本地没有正式域名也可以先申请 AK。
4. Admin（默认 `http://localhost:5173`）和 Portal 本地都走 `localhost`，**共用一把测试 JS AK 即可**。
5. APP 本地调试：另建 Android/iOS 类型 Key，Android 绑包名 + **debug** 的 SHA1；iOS 绑当前 Bundle ID。
6. 上线后再新建生产 AK（或改白名单）绑真实域名；测试 AK 可保留给开发机用。

> 本地阶段也可以暂时不申请百度 AK：继续用现有 Leaflet/OSM，不影响其它功能开发。

### 2.2 申请步骤

1. 打开 [百度地图开放平台](https://lbsyun.baidu.com/)，用公司邮箱注册并完成实名认证（个人也可申请试用，生产建议企业认证）。
2. 控制台 → **应用管理** → **创建应用**。
3. 按上表分别创建，勾选所需服务：
   - Web：**JavaScript API**（GL 版优先）
   - APP：**Android SDK** / **iOS SDK**
   - 若后续要服务端算路/逆地理，再开 **Web 服务 API**（服务端 AK，注意 IP 白名单，勿塞进前端）
4. 填写配额与安全设置：
   - JS：Referer / 域名白名单
   - Android：`applicationId` + 签名证书 SHA1（debug 与 release 可各绑一次，或同一 Key 填多个 SHA1）
   - iOS：Bundle Identifier（与 `mobile/ios` 中一致，当前一般为 `com.example...`，上线前请改成公司域名包名）
5. 保存后复制 **AK**。部分能力还需在控制台开通对应服务权限。

### 2.3 如何取 Android SHA1

```bash
# Debug
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android

# Release（替换为你们的签名库）
keytool -list -v -keystore /path/to/release.jks -alias your_alias
```

在输出中找 `SHA1:` 一行，填入百度控制台。

### 2.4 交给开发时请提供

- 四端 AK（或说明「测试环境共用一把」）
- 绑定的域名 / 包名 / Bundle ID / SHA1
- 是否已开通 JS API、Android/iOS SDK
- 日配额与是否企业认证

**禁止**：把服务端 AK 写进前端仓库；生产 AK 用环境变量或私有配置注入，勿提交 Git。

## 3. Apple APNs（E4.3 · iOS 系统通知）

需求：系统通知栏仅推送告警**摘要**，点击后走 REST 进详情。iOS 必须走 APNs。

### 3.1 推荐方式：APNs Auth Key（.p8）

比旧版 `.p12` 证书更省事：一把 Key 覆盖开发/生产，不过期（可撤销）。

1. 加入或创建 [Apple Developer Program](https://developer.apple.com/)（年费，需公司主体或个人）。
2. 打开 [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/authkeys/list)。
3. **Keys** → **+** → 勾选 **Apple Push Notifications service (APNs)** → Continue → Register。
4. **立即下载** `.p8`（只可下载一次，丢失只能作废重建）。
5. 记录页面上的：
   - **Key ID**
   - **Team ID**（Membership 页可见）
6. 确认 App **Identifiers** 中已启用 Push Notifications，Bundle ID 与 Flutter iOS 工程一致。

### 3.2 备选：APNs 证书（.p12）

旧流程：Identifiers 开 Push → 创建 Development/Production SSL 证书 → 导出 `.p12`。维护成本高，仅在对接方强制要求证书时使用。

### 3.3 交给开发 / 推送服务时请提供

| 材料 | 说明 |
| --- | --- |
| `AuthKey_XXXXX.p8` | 私钥文件 |
| Key ID | 10 位 |
| Team ID | 10 位 |
| Bundle ID | 如 `com.company.watcher` |
| 环境 | sandbox（开发）/ production（上架） |

服务端（`svc-push`）用以上材料向 APNs 发摘要；APP 侧用系统权限拿 `deviceToken` 并上报后端。

## 4. Android 推送：FCM（E4.3 基线）

海外与通用 Android 推荐先接 **Firebase Cloud Messaging (FCM)**；国内厂商通道可在 FCM 之上再叠加。

### 4.1 申请步骤

1. 打开 [Firebase Console](https://console.firebase.google.com/)，用公司 Google 账号登录。
2. **添加项目**（可关联已有 Google Cloud 项目）。
3. 添加 **Android 应用**：填写包名（与 `mobile/android` applicationId 一致）。
4. 下载 `google-services.json`，交给 Flutter/Android 工程（勿把含私钥的服务账号提交到公开仓库）。
5. 项目设置 → **服务账号** → 生成新的私钥（JSON），供后端 `svc-push` 调用 FCM HTTP v1 API。
6. （可选）同一 Firebase 项目再添加 iOS 应用，便于统一管理；iOS 真推送仍依赖上一节 APNs。

### 4.2 交给开发时请提供

| 材料 | 用途 |
| --- | --- |
| `google-services.json` | APP 侧初始化 |
| Firebase 服务账号 JSON | 后端发推送 |
| 项目 ID / 包名 | 配置核对 |

国内网络访问 Google 可能不稳定：若目标用户主要在国内，请同时规划第 5 节厂商通道，或选用支持「一次接入多厂商」的聚合推送（极光、个推、友盟等——需另开账号与商务评估，本文不绑定具体厂商）。

## 5. 国内 Android 厂商通道（E4.3 可选加深）

仅装 FCM 时，部分国产机系统通知到达率偏低。若验收要求「后台被杀仍能收到摘要」，按目标机型补：

| 厂商 | 控制台入口（以官网为准） | 常见材料 |
| --- | --- | --- |
| 华为 | 华为开发者联盟 / AGC 推送 | AppID、AppSecret、证书指纹 |
| 小米 | 小米开放平台推送 | AppID、AppKey、AppSecret |
| OPPO | OPPO 开放平台 | AppKey、AppSecret、MasterSecret |
| vivo | vivo 开放平台 | AppID、AppKey、AppSecret |
| 荣耀等 | 各厂商推送文档 | 按文档 |

流程共性：企业认证 → 创建应用 → 开通推送服务 → 绑定包名与签名 → 拿到密钥 → 后端或聚合 SDK 配置。

## 6. 相关但不在「地图/推送」内的证书

### 6.1 iOS 真机运行与上架（APP 交付）

即使不做厂商推送，真机调试也需要：

1. Apple Developer 账号。
2. **Development** 证书 + Development Provisioning Profile（调试）。
3. **Distribution** 证书 + App Store / Ad Hoc Profile（上架或内测分发）。
4. Xcode 登录同一账号，Signing & Capabilities 勾选自动签名，并打开 **Push Notifications** Capability（接 APNs 时必需）。

### 6.2 Nginx / 网关 TLS（E5.1）

| 场景 | 建议 |
| --- | --- |
| 公网域名 | Let’s Encrypt、云厂商免费证书，或购买 OV/EV |
| 内网 | 公司内部 CA 签发，客户端需信任根证书 |
| WSS | 与 HTTPS 同证书；并配置 Origin 白名单 |

材料：域名所有权、证书 `.crt`/`.pem` + 私钥 `.key`（私钥仅部署机保存）。

### 6.3 监管 SFTP Host Key（E4.1 生产加固）

代码已支持真 SFTP；生产应关闭「忽略 HostKey」：

1. 向省平台/运维索取服务器 **SSH Host Key** 指纹（或首次连接时由运维确认后写入 `known_hosts`）。
2. 若对方要求密钥登录：生成客户端密钥对，把**公钥**交给对方，私钥仅放部署环境。
3. 账号、端口、远程目录、字段映射已在 Admin「监管对接」配置；证书/密钥不要写进仓库。

- [ ] 百度 Portal JS AK + 绑定域名  
- [ ] 百度 Android AK + 包名 + SHA1  
- [ ] 百度 iOS AK + Bundle ID  
- [ ] APNs `.p8` + Key ID + Team ID + Bundle ID  
- [ ] Firebase `google-services.json` + 服务账号 JSON  
- [ ] （可选）华为/小米/OPPO/vivo 推送密钥  
- [ ] （可选）TLS 证书与私钥部署路径说明

## 8. 拿到之后怎么接进 Watcher（给开发的落点）

| 凭证 | 预期落点（实现时再改代码） |
| --- | --- |
| 百度 Web AK | Admin/Portal 地图配置或环境变量；替换 Leaflet |
| 百度 APP AK | Flutter 百度地图插件初始化 |
| APNs / FCM | `svc-push` 发摘要；APP 注册 token 并上报 |
| TLS | Nginx / 网关；`WATCHER_*` 服务反代 |
| SFTP HostKey | 部署配置，替换 insecure 回调 |

未拿到前：**不要阻塞主业务联调**；验收记录中单独标注「依赖外部凭证」。
