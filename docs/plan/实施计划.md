## 0. 总览

```
阶段 A 后端完善与服务拆分     ██████████░░  MVP 闭环；biz gRPC / 真监管 下迭代
阶段 B Web 前端（Portal+Admin）  █████████░░░  核心页+矩阵/围栏/实时解码
阶段 C Flutter APP               ████████░░░░  扫码/离线/展示/本地推送
阶段 D 联调·验收·上线验证        ██████░░░░░░  单测+集成+CI+smoke；真环境验收待办
```

**原则**

1. **后端先行**：状态机、库存口径、权限点、OpenAPI 契约先冻结，再铺页面。
2. **契约驱动**：每完成一组 API 即更新 OpenAPI / 示例请求；前端与 APP 只消费契约。
3. **垂直切片**：优先打通「入库→在库→出库锁定→运输打卡→签收」主链路，再扩告警/巡检/监管。
4. **同进程可先用**：业务逻辑先在 `backend/internal/biz` 完善；稳定后再拆 gRPC 进程，避免过早分布式调试。

## 6. 风险与缓冲

| 风险 | 缓解 |
| --- | --- |
| 过早拆微服务拖慢联调 | A2 完成前保持 biz 同进程 |
| 百度地图/推送证书耗时 | Leaflet / 本地通知先交付 |
| LDAP 环境不具备 | 配置开关；本地账号 |
| Windows 中间件兼容 | smoke `-AutoStart`；生产优先 Linux Compose |
| 监管字段蔓延 | Outbox 先骨架，字段映射配置化 |
