## 1. 文档说明

### 1.1 目的

定义后端**领域逻辑与状态机、数据库表结构、对外/对内数据格式、REST/gRPC/Protobuf/NSQ 契约**，供后端开发、联调与测试使用。前端/APP 画面见对应需求文档。

### 1.2 服务职责回顾

| 服务 | 职责 |
| --- | --- |
| `svc-webhttp` | 对外 REST、JWT+Casbin、LDAP、WSS 鉴权反代；gRPC 调 biz/history |
| `svc-mqtt` | EMQX 接入、Schema→Canonical、NSQ 发布 |
| `svc-biz` | 全部业务事务、告警/围栏、多级审批、巡检、Outbox |
| `svc-history` | MySQL 分区历史写入与查询 |
| `svc-push` | Protobuf 下行、APNs/厂商摘要推送 |

### 1.3 全局约定

| 项 | 约定 |
| --- | --- |
| 时间 | 存储 UTC；API 返回 RFC3339 或毫秒时间戳（项目内统一一种，下文用 `int64 unix_ms` + 可选 RFC3339） |
| ID | 雪花或 UUID 字符串；对外 JSON 一律 string |
| 分页 | `page`（从 1）+ `pageSize`（默认 20，最大 100）；响应 `total` |
| 错误 | HTTP 4xx/5xx + body `{ "code": "AUTH_DENIED", "message": "...", "requestId": "..." }` |
| 幂等 | 执行类请求头 `X-Idempotency-Key` 或 body `clientRequestId` |
| 鉴权 | `Authorization: Bearer <accessToken>`；端标识 `X-Client: portal\|admin\|app` |

## 2. 领域逻辑与状态机

### 2.1 唯一码 `unique_code`

```
issued(已发放) --入库确认--> in_stock(在库)
in_stock --出库确认--> in_transit(在途)   // 或经发车打卡进入在途，以实现为准但须单一路径文档化
in_transit --签收 outbound:confirm--> signed(已签收)
* --作废--> voided(已作废)   // 仅授权角色；已签收作废策略默认禁止
```

非法迁移 → `STATE_INVALID`。

### 2.2 仓储单据

| 状态 | 说明 |
| --- | --- |
| `draft` | 草稿 |
| `open` | 已开单，待 APP 执行 |
| `in_progress` | 部分确认 |
| `completed` | 全部完成 |
| `cancelled` | 作废 |

入库完成：相关码 → `in_stock`，库存增加。  
出库扫码确认：码进入在途准备；**签收** `outbound:confirm` 后码 → `signed`，库存扣减落地（若出库确认已预扣，须在实现中明确「预扣 vs 签收扣」二选一，**推荐：出库确认预留/锁定，签收才正式扣减并签收码**）。

**定论（推荐写入实现）**：

1. 出库确认：唯一码 `in_stock` → `locked`（或直接 `in_transit`）并库存锁定。
2. 签收：→ `signed`，锁定转实扣。
3. 运输打卡不单独改库存。

### 2.3 运输任务

`pending` → `in_transit`（首个发车打卡）→ `signed`（签收完成）。

打卡节点类型：`depart` / `waypoint` / `arrive`（arrive 不等于签收）。

### 2.4 告警

`raised` → `acked` → `closed`（或 raised 直接 closed）。  
仅规则引擎（阈值/围栏等）创建；用户只能 ack/close。

### 2.5 多级审批

```
pending → (level 1..N)
  第 k 级通过 → k+1 或 若 k=N → approved → 执行副作用
  任一级驳回 → rejected（无副作用）
```

模板可配：级数、每级审批人/角色、通过策略 `any` | `all`。

### 2.6 盘点

任务：`open` → `scanning` → `submitted` → `posted`（差异过账，可走审批）。

### 2.7 巡检

计划生成任务：`open` → `in_progress` → `completed`。  
点位：`pending` → `done` | `abnormal`。

### 2.8 库存变更合法来源

仅：入库确认、出库签收（实扣）、盘点过账、**审批通过**的库存调整。禁止直接 UPDATE 余额接口对外暴露。

## 4. 数据格式

### 4.1 REST 统一响应

**成功**

```json
{
  "code": "OK",
  "data": { },
  "requestId": "..."
}
```

**列表**

```json
{
  "code": "OK",
  "data": {
    "list": [ ],
    "page": 1,
    "pageSize": 20,
    "total": 100
  },
  "requestId": "..."
}
```

**错误码**

| code | 含义 |
| --- | --- |
| AUTH_DENIED | 未登录/权限不足 |
| SCOPE_DENIED | 仓范围不符 |
| STATE_INVALID | 状态机拒绝 |
| IDEMPOTENT_REPLAY | 幂等命中已成功 |
| VALIDATION_ERROR | 参数错误 |
| UPSTREAM_UNAVAILABLE | biz/history 不可用 |
| LDAP_ERROR | LDAP 失败 |

```json
  "tsUnixMs": 0,
  "warehouseId": "WH01",
  "deviceId": "DEV01",

    "temperature": 26.5,

    "lat": 0, "lng": 0, "speed": 0, "heading": 0, "accuracy": 0, "unitId": ""

```

### 4.4 PushEnvelope（Protobuf，逻辑字段）

```protobuf
message PushEnvelope {
  uint32 ver = 1;
  MsgType msg_type = 2;
  string msg_id = 3;
  int64 ts_unix_ms = 4;
  string warehouse_id = 5;
  string device_id = 6;
  oneof payload {
    Telemetry telemetry = 10;
    Location location = 11;
    DeviceEvent event = 12;
    Alarm alarm = 13;
  }
}
enum MsgType {
  MSG_TYPE_UNSPECIFIED = 0;
  TELEMETRY = 1;
  LOCATION = 2;
  EVENT = 3;
  ALARM = 4;
  HEARTBEAT = 5;
  ACK = 6;
}
message Alarm {
  string alarm_id = 1;
  string rule_code = 2;
  string level = 3;
  string title = 4;
  string status = 5;
  string metric = 6;
  double value = 7;
  double threshold = 8;
}
```

厂商通知 payload 示例（摘要）：`{ "alarmId", "level", "title", "ts" }`，不含完整曲线。

## 7. 关键业务逻辑细则

### 7.1 入库确认

1. 校验权限、Scope、幂等键。  
2. 单状态允许、码状态 `issued` 且属于该单。  
3. 事务：码→`in_stock`；写 confirmation；库存 +；ledger；Outbox/NSQ 事件。  
4. 若单据明细已满 → order `completed`。

### 7.2 签收（outbound:confirm）

1. 码处于 `in_transit` 或 `locked`。  
2. 事务：码→`signed`；库存实扣；任务可 `signed`；事件。

### 7.3 打卡

1. 任务属于当前驾驶员或授权人。  
2. 写 checkin；NSQ 位置供 history/围栏；首发车改任务 `in_transit`。  
3. **不**改唯一码签收状态。

### 7.4 围栏计算（biz 消费 location）

1. 加载启用围栏 version。  
2. 点在多边形外（含滞回）→ 产生/更新越界告警（去重策略：同单元同围栏冷却窗）。  
3. NSQ `alarm.raised`。

### 7.5 阈值告警

消费 telemetry → 比较 threshold → 抑制/滞回 → alarm。

### 7.6 多级审批副作用

仅 `approved` 时调用领域执行器（如 `ApplyStockAdjustment`）。驳回只改审批单状态。

### 7.7 巡检

校验点序（若配置强制顺序）、半径、必拍；异常可 `CreateAlarm`；全部点完成 → 任务 completed。

### 7.8 MQTT Schema

dry-run 与运行时同一套映射引擎；发布新版本后 NSQ 通知 mqtt 热加载。

## 9. 验收要点

1. 非法唯一码状态迁移全部返回 `STATE_INVALID` 且无脏写。  
2. 库存只通过合法来源变化；审批驳回库存不变。  
3. 签收与打卡权限/效果分离。  
4. 同一 `clientRequestId` 重复提交不重复入账。  
5. Canonical → history 分区可查；Push Protobuf 可解码。  
6. LDAP 登录与本地强制改密符合 V5.1。  
7. 围栏越界与超阈能生成告警并推送摘要。  
8. Outbox 失败可重试，成功不重复投递监管。
