## 1. 文档说明

### 1.1 编制目的

本文档定义智能危废管控系统的整体架构、通信组网方案、管控 APP 九大功能模块详细设计、接口规范、部署方案及与环保行政主管部门管理系统的对接标准，作为研发、实施与验收的依据。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 合规优先 | 对齐《固体废物污染环境防治法》《危险废物转移联单管理办法》《废铅蓄电池污染防治行动方案》等监管要求 |
| 一物一码 | 废铅蓄电池（或托盘/箱）唯一码贯穿申报、入库、在库、出库、运输全生命周期 |
| 多模组网 | 局域网 / 物联网 / 公网灵活切换，适配仓体现场信号条件 |
| 可落地 | 部署便捷、接口标准化，预留行政监管系统接入能力 |
| 可追溯 | 关键业务操作留痕、告警可审计、位置轨迹可回放 |

### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| 危废 | 危险废物，本文聚焦废铅蓄电池（HW31） |
| 唯一码 | 系统生成的物料/包装唯一标识（二维码/条码） |
| 暂存仓 | 危废临时贮存设施（固定仓体或可移动转运仓） |
| 运输单元 | 运输车、转运仓等可绑定定位设备的载体 |

| IoT 网关 | 汇聚传感器数据并经无线链路回传后台的边缘设备 |
| MQTT | 物联网轻量消息协议，用于传感器与设备遥测 |
| REST | 后台与 APP 主业务 API 风格 |

## 2. 业务与合规概述

### 2.1 业务范围

系统覆盖废铅蓄电池从**入库申报 → 开单入库 → 在库监测 → 盘点 → 出库 → 运输打卡/定位 → 电子围栏**的闭环管控，并对暂存仓环境（温湿度、水浸、入侵、视频）实时监测与预警。

### 2.2 监管合规要点（落地约束）

1. **转移联单关联**：出库开单、运输打卡产生的业务单号可映射危险废物转移联单编号，接口预留联单号字段。
2. **台账完整**：入库/出库/库存变动必须形成电子台账，支持按日期、仓库、唯一码查询导出。
3. **贮存规范**：库容量上限预警、库龄监控，支撑“不得超过一年贮存”等管理要求的业务提醒（可配置）。
4. **转移过程可追踪**：运输单元定位 + 打卡照片 + 唯一码扫描，形成轨迹与证据链。
5. **环境安全**：温度、湿度、水浸、入侵等超阈值即时告警并推送至责任人 APP。
6. **数据对接**：预留与生态环境部门信息系统的标准数据交换接口（见第 8 章）。

### 3.2 物理/部署架构（后台服务器）

推荐采用**混合部署**：核心业务可部署于企业机房或合规云（私有云/政务云），边缘侧按仓体就近部署网关。

```
                    ┌──────────────┐
                    │ 负载均衡 LB  │
                    └──────┬───────┘
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     ┌──────────┐   ┌──────────┐   ┌──────────┐
     │ API 节点 │   │ API 节点 │   │ MQTT 集群│
     └────┬─────┘   └────┬─────┘   └────┬─────┘
          │              │              │
     ┌────▼──────────────▼──────────────▼────┐
     │           业务与物联网微服务集群         │
     └────┬──────────────┬──────────────┬────┘
          ▼              ▼              ▼
     业务数据库     时序数据库      对象存储/备份
```

**最小可用部署（单仓试点）**：1 台应用服务器 + 1 台数据库服务器 + 1 台边缘网关。  
**规模化部署（多仓）**：K8s/容器编排，服务无状态水平扩展；MQTT、时序库独立扩容。

| 组件 | 职责 |

## 4. 通信与组网设计

### 4.1 多模式自由组网

系统支持三种组网模式，可按仓体现场条件组合或切换：

| 模式 | 适用场景 | 链路特征 | 推荐组件 |
| --- | --- | --- | --- |
| **局域网模式** | 仓内 Wi-Fi/有线完善 | 传感器 → 局域网网关 → 本地/旁路服务器；APP 可走内网 API | 工业交换机、Wi-Fi AP、边缘服务器 |
| **物联网模式** | 公网弱、需低功耗广域覆盖 | 传感器 → LoRa/NB-IoT → IoT 平台 → 后台 | LoRa 网关、NB-IoT 模组、MQTT |
| **公网模式** | 4G/5G 信号良好 | 网关/设备直连公网 MQTT/HTTPS | 4G/5G 路由器、云 Broker |

**组网决策流程**：

1. 现场勘测信号（Wi-Fi / 蜂窝 / 无信号盲区）。
2. 优先局域网汇聚，无可靠局域网则启用蜂窝公网网关。
3. 偏远或低功耗传感器采用 NB-IoT/LoRa，经网关汇聚后统一 MQTT 上行。
4. 支持**双链路冗余**（主链路故障自动切换备用 4G）。

### 4.2 传感器数据采集与回传完整链路

```
[温湿度/水浸/入侵传感器]
        │  RS485 / Modbus / Zigbee / 私有无线
        ▼
[仓内采集器 / IoT 网关]
        │  协议转换、本地缓存、断点续传、边缘阈值初判
        ▼
[无线网络设备]  ← Wi-Fi / 以太网 / 4G·5G / NB-IoT / LoRa
        │  MQTT Publish（telemetry）或 HTTPS 批量上报
        ▼
[MQTT Broker / 接入服务]
        │  鉴权、Topic 路由、QoS
        ▼
[物联网服务：解析 → 时序入库 → 规则引擎]
        │
        ├─→ 超阈值 → 告警服务 → 推送 APP / 短信
        ├─→ 实时数据 → WebSocket/SSE → APP 智能监测页
        └─→ 视频流 → 流媒体服务 → APP 播放（RTSP→HLS/WebRTC）
```

**关键保障**：

- **本地缓存**：网关离线时缓存不少于 72 小时遥测，恢复后补传。
- **时间同步**：NTP；报文携带设备时间戳与网关接收时间戳。
- **QoS**：告警类 QoS1/2；常规温湿度 QoS0/1 可配置。
- **安全**：设备证书或预共享密钥；Topic 按租户/仓体隔离。

### 4.3 后台与管控 APP 无线通信协议与传输规范

#### 4.3.1 协议选型

| 通道 | 协议 | 用途 |
| --- | --- | --- |
| 业务 API | HTTPS + JSON（REST） | 开单、查询、配置、报表 |
| 实时推送 | WSS（WebSocket）或厂商推送 | 告警、任务状态 |
| 文件上传 | HTTPS multipart | 照片、盘点附件、导出 |
| 地图 | HTTPS（地图 SDK） | 运输定位、电子围栏 |

**不采用明文 HTTP**；证书采用企业 CA 或权威 CA，支持证书锁定（可选）。

#### 4.3.2 传输规范

| 项 | 规范 |
| --- | --- |
| 编码 | UTF-8；JSON `Content-Type: application/json` |
| 时间 | ISO 8601，统一 UTC 存储，APP 按本地时区展示 |
| 鉴权 | `Authorization: Bearer <JWT>`；刷新令牌旋转 |
| 幂等 | 写操作携带 `Idempotency-Key`（开单、打卡） |
| 分页 | `page` / `pageSize` / `total` |
| 错误码 | 统一 `{ code, message, detail }` |
| 压缩 | 大列表支持 gzip |
| 限流 | 按用户/设备；扫码接口防刷 |
| 离线 | APP 本地队列缓存关键操作，恢复网络后同步并冲突提示 |

#### 4.3.3 MQTT Topic 约定（设备侧）

```
hw/{tenantId}/warehouse/{warehouseId}/telemetry/{deviceId}   # 遥测上报
hw/{tenantId}/warehouse/{warehouseId}/event/{deviceId}       # 告警/事件
hw/{tenantId}/unit/{unitId}/location                         # 运输单元定位
hw/{tenantId}/device/{deviceId}/cmd                          # 下行指令
```

遥测报文示例：

```json
{
  "deviceId": "TH-001",
  "warehouseId": "WH-A01",
  "ts": "2026-10-15T06:20:00Z",
  "metrics": {
    "temperature": 28.5,
    "humidity": 62.0,
    "waterLeak": false,
    "intrusion": false
  },
  "battery": 86,
  "rssi": -67
}
```

#### 4.3.4 REST 通用响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "a1b2c3d4"
}
```

## 5. 管控 APP 功能模块详细设计

> 原型页面见 `prototypes/` 目录，与本节一一对应。

### 5.0 全局交互与数据流通则

- **角色**：仓管员、驾驶员/押运员、安全员、管理员（权限矩阵控制菜单与按钮）。
- **主框架**：底部 Tab（首页 / 仓储 / 运输 / 监测 / 我的）；各模块由首页宫格或二级菜单进入。
- **扫码入口**：统一调用相机扫码组件，解析唯一码后按业务上下文跳转。
- **数据流转**：APP → API Gateway → 业务服务 → DB；告警类由规则引擎异步推送回 APP。

---

### 5.1 仓储管理模块

#### 5.1.1 功能目标

废铅蓄电池**入库申报、入库开单、出库开单**全流程线上化；唯一码生成、发放与全生命周期关联。

#### 5.1.2 交互逻辑与操作流程

**A. 入库申报**

1. 选择暂存仓 → 填写产生单位、重量/数量、危废代码（HW31）、拟入库时间。
2. 提交生成《入库申报单》，状态：待审核 / 已通过 / 驳回。
3. 审核通过后方可进入入库开单（权限可配置为免审）。

**B. 入库开单**

1. 关联申报单（或直接开单）→ 系统生成入库单号。
2. 按件/按托盘生成唯一码（批量），预览并打印/发放二维码。
3. 扫码确认上架库位 → 提交入库 → 库存增加，台账写入，唯一码状态=`在库`。

**C. 出库开单**

1. 选择仓库与去向（接收单位、联单号可选）→ 扫码拣选在库物资。
2. 校验：非在库不可出；库容/联单字段完整性校验。
3. 提交出库 → 库存扣减，唯一码状态=`在途`，可自动创建运输任务草稿。

#### 5.1.3 数据流转

```
申报单 → 审核 → 入库单 + 唯一码批次 → 库存明细 + 台账
出库单 + 扫码明细 → 库存扣减 → 运输任务(可选) → 联单映射字段
```

#### 5.1.4 唯一码规则（建议）

`HW31-{企业码}-{年月日}-{流水号}`，二维码载荷含 `uniqueCode` + 校验位；全生命周期状态：`已发放 → 在库 → 在途 → 已签收 → 作废`。

### 5.2 物资管理模块

#### 5.2.1 功能目标

多维度查询暂存危废在库情况：基础信息、实时库存量、库龄等。

#### 5.2.2 交互逻辑

1. 进入物资列表，默认展示当前用户有权限的仓库汇总。
2. 筛选：仓库、危废代码、库位、库龄区间、状态、关键词（唯一码/名称）。
3. 点击条目进入物资详情：基础属性、库存量、入库时间/库龄、关联单据、当前位置（仓内库位）。
4. 支持导出当前筛选结果（异步生成 Excel，APP 内下载或邮件）。

#### 5.2.3 数据流转

```
筛选条件 → GET /materials → 聚合库存视图 → 详情 GET /materials/{id}
```

核心展示字段：唯一码、危废名称/代码、数量/重量、仓库/库位、入库时间、库龄（天）、状态。

---

### 5.3 库存盘点模块

#### 5.3.1 功能目标

选择目标仓库，扫码快速盘点，自动生成标准化盘点报表并导出。

#### 5.3.2 操作流程

1. 新建盘点任务 → 选择仓库（可指定库区）。
2. 系统拉取应盘清单（账面库存）。
3. APP 连续扫码录入实盘；支持手动补录异常说明。
4. 实时对比：相符 / 盘盈 / 盘亏。
5. 提交盘点 → 生成报表（PDF/Excel）→ 支持导出与归档。
6. 盘盈盘亏可触发复盘或走库存调整审批流（可配置）。

#### 5.3.3 数据流转

```
盘点任务 → 应盘快照 → 扫码实盘明细 → 差异计算 → 报表文件 → 对象存储
```

---

### 5.4 预警管理模块

#### 5.4.1 功能目标

自定义暂存仓环境预警阈值（温度上下限、湿度上下限、库容量上限等）；达阈值时推送提醒与告警。

#### 5.4.2 交互逻辑

1. 选择仓库 → 进入阈值配置页。
2. 设置：温度下限/上限、湿度下限/上限、库容上限（% 或吨）、水浸/入侵（开关型默认即告警）。
3. 设置通知对象、静默时段、告警级别（一般/重要/紧急）。
4. 保存后下发规则引擎；历史告警列表可筛选、确认、转工单。

#### 5.4.3 触发与推送

```
遥测/库存事件 → 规则引擎比对阈值 → 生成告警记录
  → 推送网关 → APP 推送 + 站内消息 +（可选）短信
```

APP 收到推送可深链至「智能监测」或「告警详情」。

---

### 5.5 运输打卡模块

#### 5.5.1 功能目标

扫描物料唯一码、拍摄现场照片，自动采集物料信息与实时位置，完成运输全流程跟踪打卡。

#### 5.5.2 操作流程

1. 选择/扫码关联运输任务（或出库单）。
2. 扫唯一码 → 回填物料信息。
3. 拍照（至少 1 张，可配置必拍角度）。
4. 自动获取 GNSS 位置（经纬度、地址逆地理、定位精度）。
5. 选择打卡节点：发车 / 途经 / 到达 / 异常。
6. 提交 → 服务端校验唯一码与任务归属 → 写入轨迹点与附件。

#### 5.5.3 数据流转

```
扫码+照片+GPS → POST /transport/checkins → 任务进度更新 → 轨迹点入库
```

离线时本地加密缓存，恢复后补传（保留原始定位时间）。

---

### 5.6 运输单元管理模块

#### 5.6.1 功能目标

管理**运输车、转运仓**两类运输单元；支持绑定定位设备，实现位置跟踪基础能力。

#### 5.6.2 管理逻辑

| 单元类型 | 主数据字段 | 绑定能力 |
| --- | --- | --- |
| 运输车 | 车牌、车型、载重、驾驶员、状态 | 绑定 GPS/北斗定位终端 |
| 转运仓 | 仓体编号、容积、所属仓库关系、状态 | 绑定定位终端（可移动仓） |

操作：新建/编辑单元 → 扫描或输入定位设备 ID → 绑定/解绑 → 启用跟踪。

#### 5.6.3 数据流转

```
单元主数据 ↔ 定位设备注册表；设备定位上报 → 单元最新位置视图
```

### 5.7 运输定位跟踪模块

#### 5.7.1 功能目标

APP 内置地图组件，实时展示所有运输单元位置，全景可视化。

#### 5.7.2 交互逻辑

1. 打开地图页，拉取有权限的运输单元最新位置。
2. 地图标注区分运输车 / 转运仓图标；点击弹出卡片（名称、速度、更新时间、关联任务）。
3. 支持列表与地图联动、按状态筛选（在途/静止/离线）。
4. 进入单元详情可查看历史轨迹回放（时间轴）。
5. 定位数据通过 WSS 或短轮询（15–30s）刷新。

#### 5.7.3 数据流转

```
定位终端 → MQTT location → 定位服务 → APP 地图图层
```

---

### 5.8 软电子围栏模块

#### 5.8.1 功能目标

为暂存仓（尤其可移动转运仓）设置自定义软电子围栏；位置越界自动预警。

#### 5.8.2 操作流程

1. 选择目标仓/单元 → 进入围栏编辑。
2. 地图上绘制圆形（中心+半径）或多边形顶点。
3. 设置生效时段、告警方式、缓冲滞回（防抖，如越界持续 N 分钟再告警）。
4. 保存 → 规则引擎按定位点做点面关系判断。
5. 越界 → 告警推送；回栏可自动恢复或需人工确认。

#### 5.8.3 数据流转

```
围栏 GeoJSON → 规则引擎；定位点 → 空间计算 → 越界事件 → 推送
```

---

### 5.9 智能监测模块

#### 5.9.1 功能目标

集成温度、湿度、水浸、入侵、监控视频等多源数据，实时可视化监测仓内环境。

#### 5.9.2 页面与交互

1. 选择暂存仓 → 总览仪表盘：当前温湿度、库容占用、传感器在线状态、未处理告警数。
2. 环境卡片：温度/湿度曲线（近 24h/7d）；水浸/入侵状态灯。
3. 视频：列表选通道 → HLS/WebRTC 播放；支持抓图关联告警。
4. 下拉刷新；异常指标标红并跳转预警详情。

#### 5.9.3 数据流转

```
传感器 MQTT → 时序库 → 监测 API / WS 推送 → APP 图表
摄像头 → 流媒体 → APP 播放器
```

## 7. 部署方案

### 7.1 环境划分

| 环境 | 用途 |
| --- | --- |
| 开发环境 | 联调、模拟传感器 |
| 测试/预发 | 验收、压力与安全测试 |
| 生产环境 | 正式运行，双机或集群 |

### 7.2 仓体现场部署清单（典型）

| 设备 | 数量建议 | 说明 |
| --- | --- | --- |
| IoT 网关 | 1/仓 | 协议转换、缓存、链路冗余 |
| 温湿度传感器 | 按库区 | 建议关键点位双探头 |
| 水浸传感器 | 低洼点 | 开关量 |
| 入侵传感器 | 门禁/红外 | 与视频联动 |
| 摄像头 | 出入口+库内 | 国标/ONVIF |
| 4G/5G 路由 | 1（可选） | 公网备份链路 |
| 定位终端 | 按运输单元 | 北斗/GPS |

### 7.3 部署便捷性设计

- 网关开箱：扫码绑定仓体，自动拉取配置。
- APP 下载企业分发或应用市场；首次登录选择租户/组织。
- 组网向导：局域网 / 物联网 / 公网三选一或组合，后台可视化拓扑。
- 传感器即插即用模板（Modbus 点表预设）。

### 7.4 安全与运维

- 全链路 TLS；设备双向认证；最小权限 RBAC。
- 审计日志：登录、开单、阈值变更、围栏变更、导出。
- 备份：业务库每日全备 + 日志增量；时序数据保留策略可配（建议 ≥1 年关键告警）。
- 监控：服务存活、MQTT 连接数、网关在线率、磁盘。

## 8. 与环保行政主管部门管理系统对接标准

### 8.1 对接目标

向生态环境主管部门信息系统按标准格式推送或供其拉取：**产生/入库/出库台账、转移联单关联信息、暂存库存、转移轨迹摘要、重大环境告警**等。

### 8.2 对接方式

| 方式 | 说明 |
| --- | --- |
| 推送（Push） | 业务事件发生后，系统调用对方开放 API 或省平台交换节点 |
| 拉取（Pull） | 对方调用本系统 OpenAPI 查询 |
| 文件交换 | 约定周期生成 XML/JSON/CSV 报文至 SFTP（兜底） |

### 8.3 数据交换规范（建议字段集）

**台账类报文** `WasteLedger`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| enterpriseCode | string | 单位编码 |
| wasteCode | string | 危废代码，如 HW31 |
| uniqueCode | string | 唯一码 |
| direction | enum | IN / OUT |
| quantity | number | 数量 |
| unit | string | 吨/只 等 |
| occurTime | datetime | 业务时间 |
| warehouseCode | string | 贮存设施编码 |
| manifestNo | string | 转移联单号（可空） |
| operator | string | 操作人 |

**告警类报文** `EnvAlarm`：仓库编码、告警类型、阈值、实际值、发生时间、处置状态。

**轨迹摘要** `TransferTrackSummary`：联单号、运输单元、起止点、关键打卡节点时间与坐标。

### 8.4 安全与管理

- 国密或 TLS1.2+；OpenAPI 使用 AppId + 签名（HMAC-SHA256）或双向证书。
- 对接开关、字段映射、重试与死信队列可配置。
- 提供对接日志查询与人工重推能力，满足监管抽查。

### 8.5 接口示例（本系统 OpenAPI）

```
GET  /api/v1/open/ledgers?from=&to=&page=
GET  /api/v1/open/inventory/snapshot?warehouseCode=
GET  /api/v1/open/alarms?level=CRITICAL&from=
POST /api/v1/open/manifests/bind   # 联单号与出库单绑定回写
```
